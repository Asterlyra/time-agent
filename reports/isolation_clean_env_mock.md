# 干净环境与隔离验证：本地模拟

本记录只验证环境变量白名单的原理，不启动 Codex、模型或网络；没有复制、读取或显示任何真实密钥，也没有重试此前自动审批拒绝的测试。复现：`python -m unittest tests.test_isolation_mock -v`。

模拟父进程持有一个无意义的假凭据和一个假控制管道，子进程只继承 Windows 的 SystemRoot/WINDIR；测试确认假凭据与管道变量都没有传给子进程。同时子进程仍能读取专门创建的无敏感 canary 文件，说明**清理环境变量不能隔离文件系统**。两个测试通过。

当前 `src/adapters/codex_mxc.py` 仅排除了四个变量，其他变量仍会继承，不能将其称作无敏感环境。即使完全清理变量，进程仍可能通过当前用户的文件权限、系统凭据库、已登录的服务或网络获取资源。实验模型不能直接继承用户密钥，也不应能读取用户工作区或身份凭据。

## 建议的验证设计

1. 使用独立的操作系统安全主体或专用虚拟机，以最小权限运行模型侧执行环境；不挂载本机工作区、答案、用户配置或凭据目录。准备无秘密的临时目录及随机 canary，明确每个尝试的边界。
2. 在不涉及模型或真实凭据的本地测试中，验证文件、进程环境、其他账户凭据库、外部工具与非必要网络访问；包括允许访问的对照和拒绝访问的负向对照，记录时间、配置和退出状态。控制层可向环境提供无敏感数据的假请求和假响应。
3. 模型服务身份必须通过经批准的隔离架构接入，例如在单独受信任的网关中持有专用凭据并限定唯一目标；其可行性、凭据来源及部署方式目前尚未确定。清洁模型侧环境不能自行保证此部分安全。
4. 在取得可运行的受控架构后，再单独验证完整调用链、允许的模型连接、工具禁用、已知 canary 不可读以及事件日志完整。任何不能验证的路径都必须标明，不以一次模型没有调用工具证明其无法访问。

## 当前结论

本地模拟只证明一个子进程没有继承两个虚构变量，并证明无操作系统隔离时 canary 可读；它不验证 MXC、Codex、真实凭据读取、网络隔离或完整模型执行链。正式实验的隔离条件尚未通过；原开发轨迹仍为探索性数据。
