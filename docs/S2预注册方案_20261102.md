# S2 预注册方案：截止预算下的部分计分信息收集

> 状态说明（2026-11-02 收尾）：本方案已按原样执行完毕，正式批次为 `runs/s2-formal-20261102T035658599154Z`（432/432 闭合，其中 6 条为宿主休眠环境失败）。结果见 `runs/s2-formal-20261102T035658599154Z/stats_summary.json`、`docs/执行记录S2_20261102.md` 与 `paper/main.md`。以下冻结内容未作修改。

冻结时间：2026-11-02（正式批次启动前写定）。本文件在正式批次产生任何结果之前写定，之后不再修改参数、指标或分析规则；任何基于正式结果的改动都必须作为新批次登记，并与本批次分开报告。文末“修订记录”逐条说明 pilot 之后改了什么、为什么改。

## 1. 研究问题

S1 已执行 1080 次正式配对实验：工具由快变慢时，动态摘要 C 相对固定摘要 B 的成功率差为 +0.83 个百分点，95% 区间 [−5.83, +8.33]，未确认方向性收益。S1 的设计使这一零结果在理论上可预期：

1. v4 任务的正确路径唯一（收集全部必需行后提交），延迟估计不改变最优动作，摘要因此没有作用通道；
2. 两模型成功率接近天花板（GLM 332/360、DeepSeek 346/360），二元结局进一步压缩了可检出差异。

S2 的问题是：**当正确动作确实依赖于“下一次调用要花多久”时，不同延迟参考接口是否会改变智能体的停止决策与得分？**

## 2. 环境

单次 episode 给出固定 wall-clock 预算与 20 个不透明编号（K01–K20）。唯一工具 `fetch(item_id)` 返回该编号的四位整数值，并消耗一段由宿主注入的时间。智能体可随时回复 `{"type":"submit"}` 结束本局；宿主按“已成功获取的不同编号数”计分，每个 1 分。若预算耗尽时仍未完成 submit，本局 0 分，已获取编号作废。

关键设计点：

1. **部分计分**：得分是 0–20 的整数，不是二元的“全对/失败”，因此不存在 S1 的天花板压缩方差问题。
2. **停止动作有代价也有效用**：继续 fetch 增加得分但消耗时间；停止保住已有得分。这是延迟信息唯一可能改变最优动作的地方。
3. **提交无载荷**：宿主结算它实际发出的数值，智能体不需要回述不断增长的字典。第一个 pilot 用带载荷提交，一个模型取到 7 个值却只提交 1 个，说明那样测的是上下文复述能力而非停止决策，该版本作废。
4. **状态外显**：observation 始终包含 `collected_items`（已获取编号与数值、计数、剩余编号数），四个条件相同，用于把记忆负担从停止决策中移除。

### 2.1 延迟剖面

调用耗时由**工具开始时刻**决定：

| 剖面 | 公式 | 含义 |
|---|---|---|
| `stable_fast` | `d = 8 s` | 对照：先验正确，无需适应 |
| `fast_to_slow` | `d = 8 s`（t < 30% 预算），其后 `d = 60 s` | 阶跃下降：一次观测即可发现 |
| `drift_up` | `d(t) = 8 × 7.5^(t/200)`，从 8 s 几何漂移到 60 s | 渐进退化：最近一次观测**总是**低估下一次 |

`drift_up` 是主剖面。理由是：阶跃变化只要发生一次调用就能被观测到，因此任何“反应式”参考都只是重复历史；而几何漂移使“最近一次观测”系统性低估下一次调用，估计偏差会在整个 episode 中持续存在。只有在这种结构中，参考接口才可能产生可检测且方向可预期的差异。这一推理由 §8 的离线规划器模拟支撑。

## 3. 条件（信息阶梯）

四个条件在问题、工具、预算、时钟和 `collected_items` 上完全一致，唯一差别是 observation 中的 `duration_reference_s`：

| 条件 | observation 中的延迟参考 |
|---|---|
| A | 无 `duration_reference_s`（只有原始历史、`elapsed_s` 与 `calibration_samples_s`） |
| B | 每个工具的固定先验：开局前校准样本均值（8 s） |
| C | 每个工具**最近一次**完整调用的实测耗时；首调用前回退到校准均值 |
| O | 宿主在当前时刻实际施加的耗时（完美瞬时预言机；非可部署接口，用作信息上界） |

`calibration_samples_s` 在所有条件下均可见，因此 A 与 B 的差别是“是否给出合成后的单个数字”，而不是“是否知道任何耗时信息”。这一点与 S1 一致，便于对照。

C 的窗口由 S1 的 3 改为 1：在 45–60 s 工具延迟与 200 s 预算下，三次滑动均值在阶段切换后仍会给出 16.7 s（真值 45 s，见 pilot 2），把“估计器滞后”与“接口是否改变行为”混在一起。窗口 1 在第一次观测后即为准确值，从而隔离出“当前估计是否改变停止决策”。S1 使用窗口 3，两轮不可直接相加比较。

## 4. 冻结参数

| 项目 | 值 |
|---|---|
| 模型 | `glm-5.3-flash`、`qwen3.8-flash`、`deepseek-v4.1-flash` |

| 剖面 | 3（stable_fast / fast_to_slow / drift_up） |
| 条件 | 4（A/B/C/O） |
| 预算 | 每模型 200 s（统一，不按模型调节） |

| 工具延迟 | 快 8.0 s，慢 60.0 s |
| C 的窗口 | 1 |
| max_steps | 32 |
| 并发 | 每模型 2，全局 6 |
| manifest seed | 20261102 |
| 计划 episode 数 | 3 × 12 × 3 × 4 = 432 |

每个 block = (模型, 任务, 剖面) 的四个条件相邻执行，条件顺序在 block 内轮换（四个条件在四个位置上各出现一次），以控制服务负载漂移。

## 5. 假设

- **H1（持续偏差下的收益）**：`drift_up` 下 C 的得分高于 B。
- **H2（先验过时即有害）**：`drift_up` 下 B 的得分不高于 A，即一个过时的合成参考不比不提供参考更好。
- **H3（预测优于观测）**：`drift_up` 下 O 的得分高于 C；差距衡量“提前知道”相对“事后观测”的额外价值。
- **H4（阶跃情形无持续偏差）**：`fast_to_slow` 下 C−B 的方向与 H1 相同但幅度更小；因为一次慢调用就足以被观测到，参考的边际信息更少。
- **H5（无冗余时无差异）**：`stable_fast` 下四个条件不应出现方向性差异（先验正确，C 观测到的就是 8 s，O 等于 8 s）。

## 6. 指标

**主指标**：`drift_up` 下 C−B 的配对得分差，三模型等权平均。

**次指标**：

1. 其余配对差（B−A、C−A、O−A、O−B、O−C），以及 `fast_to_slow`、`stable_fast` 下的同一组差值。
2. 提交率（`termination_reason == 'submitted'`）。
3. 最后一次 fetch 时的剩余时间 `last_fetch_remaining_s`：停止决策的直接行为指标。
4. 提交时的剩余时间。
5. fetch 次数、重复 fetch 比例、无效动作比例。
6. 参考值与实际耗时之差（B 与 C 的参考误差）。
7. 与离线理性规划器（B/C/O 三种信念）的期望得分对比，衡量“可用价值的捕获率”。

## 7. 分析计划

- 推断单位是 block（模型 × 任务 × 剖面）。任务实例是同一场景的不同随机实例，属于可交换重复，不是独立题库条目；因此只对“该受控场景”推断，不宣称对任务总体推广。
- 配对簇 bootstrap：每个剖面单独重采样任务索引，同一次抽样用于三个模型（保持配对），三模型等权平均；10000 次，seed 911，报告 95% 百分位区间。
- 随机化检验：对每个 block 的模型平均差值作符号翻转，2000 次，报告双侧 p。
- 单模型区间为探索性，不作多重比较校正；主结果以三模型等权为主。
- 不做可选停止：一次性跑完 432 条后分析，不按中途结果增减样本。

## 8. 设计有效性检查（离线，无需模型）

`scripts/study2_simulate.py` 用 S1 正式批次中每个模型的实测请求墙钟时间重采样，模拟三种信念的理性规划器。设计须满足：

1. 可行动空间：`drift_up` 下 C 与 B 的模拟期望得分差 ≥ 3 个物品。
2. 无天花板：任何剖面下模拟期望得分 < 20。
3. 无地板：C 在 `drift_up` 下的模拟期望得分 ≥ 3。

当前参数下的模拟值（seed 7，每格 600 次）：

| 剖面 | 模型 | B | C | O |
|---|---|---:|---:|---:|
| stable_fast | GLM / DeepSeek / Qwen | 14.9 / 15.3 / 6.0 | 同左 | 同左 |
| fast_to_slow | GLM / DeepSeek / Qwen | 5.3 / 5.5 / 0.6 | 7.1 / 7.1 / 3.4 | 同 C |
| drift_up | GLM / DeepSeek / Qwen | 2.1 / 2.8 / 2.4 | 7.3 / 7.3 / 3.9 | 8.5 / 8.6 / 4.6 |

三项检查均满足。

## 9. 质量与报告规则

- 服务错误、协议错误、宿主休眠导致的 `environment_interruption` 全部保留；不重跑、不删除。若出现宿主休眠，按连续钟口径记为环境失败，并在报告中单列。
- 若实际提交率过低导致地板效应，按原样报告并明确说明限制，**不**据此更换参数重跑正式批次。
- 条件 O 是信息上界，不是可部署方案；所有 O 的结果只用于分解“信息价值”与“行为缺口”。
- 三个模型的绝对分数不可直接作为能力排名：请求墙钟时间、服务端路由与默认推理设置都是被测组合的一部分。

## 10. 与 S1 的关系

两轮实验共同回答一个更大的问题：**时间信息什么时候有价值**。S1 提供“无杠杆 → 无收益”的对照，S2 提供“有杠杆 → 收益及其边界”的对照。两轮环境、任务、计分与预算不同，不能把两轮数值合并成单一效应量；本文把它们作为同一理论命题的两个互补检验。

## 12. 修订记录

1. **提交去载荷**（pilot 1 后）：避免把上下文复述能力计入因变量。
2. **窗口 3 → 1**（pilot 2 后）：避免估计器滞后与接口效应混淆。
3. **剖面集合改为 stable_fast / fast_to_slow / drift_up**（pilot 3 后）：pilot 3 显示阶跃变化被一次观测完全吸收，四条件无差别；`drift_up` 制造持续的估计偏差，是唯一能让“参考是否有效”可识别的结构。`slow_to_fast` 因此移出正式批次。
4. **主指标剖面改为 `drift_up`**：与第 3 条同一理由；该选择基于离线规划器模拟与 pilot 行为，不基于任何正式结果。
