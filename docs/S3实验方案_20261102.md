# S3 实验方案：信息、承诺、强制——时间模型该由谁持有

状态：**待确认**。确认后先冻结为预注册文件，再开始 P0。

## 1. 从 S1/S2 得到的定位

S1（1080 条）证明：当任务的正确路径唯一时，延迟摘要不可能改变最优动作。
S2（432 条）证明：即使给了决策杠杆，四档信息（无 / 静态先验 / 自适应 / 预言机）也产生完全相同的行为——参考值误差 8.0 s vs 1.5 s，而停止阈值只在 54.9–62.0 s 之间移动，主对比 −0.36 个物品（95% CI [−1.1, +0.4]）。

由此得到的判断不是"模型不吃时间信息"，而是：**模型只吃时钟，不吃别人替它算好的估计**。于是问题自然转向——如果模型拿不住时间模型，是不是应该由 harness 拿？

## 2. 科学问题与假设

**问题**：在硬截止、随机且异质的调用代价下，哪一类干预真正改变停止行为与产出：给它信息、让它承诺，还是由 harness 强制执行？

- **H1（信息无效）**：`I1`（估计 + 排序提示）相对 `I0`（仅时钟）在产出上没有实质提升。
- **H2（承诺部分有效）**：`C`（模型自己声明预留量、harness 按声明执行）优于 `I0`，但显著劣于 `E`。
- **H3（强制有效但有代价）**：`E`（harness 持有自适应时间模型）显著优于 `I0` 与 `C`，并回收 `O−I0` 差距的大部分；代价是在重尾区制下过度保守，少取一部分物品。
- **H4（区制依赖）**：尾部越重，`E` 的回收率越低——这是"把时间模型放进 harness"这一建议的适用边界。

同一个规则、不同执行者（`C` vs `E`）是本设计的关键对照：它把"规则好不好"与"谁来执行"分离开。

## 3. 环境 v7

### 3.1 两个任务族

| 族 | 结构 | 为什么需要 |
|---|---|---|
| `uniform` | 16 个 item，各值 1 分；每次 fetch 的耗时从对数正态抽样 | 对应 S2 的基线，保证与上一轮可比 |
| `hetero` | 16 个 item，公开标注价值 v∈{1,3,5} 与体量 s∈{S,M,L}；耗时按 s 取不同均值的对数正态 | 停止变成价值密度决策（该不该赌一个 L 项），是"估计分布"真正有用的地方 |

每族的 28 个任务实例随机化结构参数（item 数 14–18、价值分布、S/M/L 的均值比、预算档位），因此不是同一模板换随机数。

### 3.2 随机、重尾的延迟

每次调用耗时独立抽取：`d ~ LogNormal(μ(size) - σ²/2, σ)`，均值即 μ。σ=1.0（重尾），随机种子随 episode 记录并可复现。

这与 S2 的确定性阶跃/漂移不同：**单次观测不再等于均值**，估计在原理上重新有价值——这正是审稿人会问的那一点。

### 3.3 三个区制

`fast_heavy`（μ=8 s）、`slow_heavy`（μ=25 s）、`drift_heavy`（μ 在 episode 内 8→25 s 线性上升）。区间由 **已用预算比例** 决定，与 S2 一致。

## 4. 五档干预（唯一差别是可执行的动作集合）

| 代号 | 观测里多什么 | harness 多做什么 | 测什么 |
|---|---|---|---|
| `I0` | 时钟 + 已取 item | 无 | 基线 |
| `I1` | + 成本均值/p90 + 剩余高价值项提示 | 无 | 信息是否够 |
| `C` | 同上 + 必须提交 `commit{reserve_s}` | 按**模型声明的**预留量执行 | 规则×模型执行 |
| `E` | 同上 | 按**实测分布自适应**的预留量执行，拒绝不可能完成的 fetch | 规则×harness 执行 |
| `O` | 同上 | 用真实分布算期望最优停止点并执行 | 上界 |

`C`/`E`/`O` 都由 harness 机械执行同一件事——"剩余时间低于预留量时强制提交"——只是预留量分别来自模型声明、实测自适应估计、真实分布。因此三者的差异是**预留量从哪来**，不是"有没有护栏"。

**安全性**：所有档位下，模型仍然可以是任何输出；被拒绝的 fetch 会返回一条固定文案并消耗一次请求，不额外惩罚。

## 7. 指标与统计

**主指标**：`hetero` 族的得分（采集到的价值总和；未在截止前提交记 0），三区制合并，**E − I0**，四模型等权。

**关键次指标**：
1. `E − O`：回收率 = (E−I0)/(O−I0)。
2. `C − I0` 与 `C − E`：隔离"规则"与"执行者"。
3. `I1 − I0`：复现 S2 的零结果。
4. 截止失败率、最终预留量、决策时剩余时间的分布。
5. 分模型、分族、分区制。

**统计**：以 block 为簇的配对 bootstrap（10,000 次，seed 固定）、符号翻转随机化检验；主对比报 95% 区间与精确 p。全量失败保留，环境中断单列。

**预注册的质量检查（P2 之前跑，不依赖正式结果）**：
- 离线规划器模拟必须显示 `O − I0 ≥ 3` 分，否则环境没有可回收的价值。
- `E` 的模拟得分必须严格介于 `I0` 与 `O` 之间，否则护栏退化为复制预言机。
- 任一单元不得触到 16 项满分天花板。

## 8bis. 两阶段设计与提前停止

阶段 A（6,930 条）与阶段 B（再 6,930 条）构成**两次 look 的群序贯设计**，不是"看结果再决定加样本"：

- 每次 look 使用单侧边界 **z ≥ 1.875**（名义 α ≈ 0.030）；两次 look 合计保持单侧 α = 0.05（Pocock 型常数边界）。
- 阶段 A 结束若过界 → 停止，以阶段 A 作为结果报告。
- 未过界 → 执行阶段 B，在最终 look 用同一界判定。
- **无论是否过界，两个阶段的数据都完整报告**；若阶段 A 过界而仍执行 B，则 B 作为独立复现单独报告，不并入主估计。
- 阶段 B 的任务实例、随机种子与阶段 A 完全独立。

这样"先跑 48 小时看效果、有希望再补到 96 小时"不会抬高一类错误率。

## 8ter. 宿主休眠的预防与代价

本机 `pmset` 显示空闲休眠阈值是 **1 分钟**，当前仅被其它应用（`UURemote`、`coreaudiod`）的断言临时按住；S2 的 437 秒休眠即由此产生。

预防（全部无需 root）：

1. 批次进程整体跑在 `caffeinate -dims -u` 下，持有显示、空闲、磁盘与系统断言；
2. 守护进程每 60 秒调用一次 `caffeinate -u -t 2`，重置用户活动计时器——即使别的应用撤掉断言，1 分钟空闲也不会触发；
3. `scripts/supervise.py` 在子进程退出后自动：核对归档源码逐字节一致 → 归档休眠失败 → 续跑，最多 40 次重启；
4. 批次期间保持接入电源（`-s` 断言只在交流电下生效）。

代价：

- **对测量零影响**：`caffeinate` 只作用于宿主电源状态，不触碰模型、网络或注入的等待。
- **残余损失**：若合盖或人为休眠，当时在飞的 episode（每 worker 一条，最多 8 条）被判环境失败，按 0 分计入分母并原样归档。阶段 A 每次事件 ≤ 8/6,930 ≈ 0.12%。
- **统计影响**：要损失 1% 需约 9 次事件。预注册两项检查：按干预分组的环境失败数均衡性检验；以及"剔除 / 置 0"两种口径的敏感性分析。
- 说明：连续钟包含休眠，跨休眠的 episode **必须**作废——否则智能体可以通过让宿主休眠来"冻结"截止时间。


## 8quater. 中期分析（2026-11-02 20:40 补记，在任何结果被计算之前）

原因：阶段 A 实测吞吐约 2.7 条/分钟，7,040 条需要约 37 小时，超出单次值守窗口。
为使"主结论不依赖长跑是否跑完"，在原两次 look 之前增加一次**运营性中期分析**，
并使三次 look 的边界仍满足单侧 α = 0.05。

**三次 look 的 Pocock 常数边界**：单侧 z ≥ 2.01（每次名义 α ≈ 0.022），
三次合计单侧 α = 0.05。

| Look | 触发点 | 条数 | 判定 |
|---|---|---|---|
| 1 | 阶段 A 的 25% | 1,760 | z ≥ 2.01 → 停止并按该 look 报告；否则继续 |
| 2 | 阶段 A 完成 | 7,040 | z ≥ 2.01 → 停止；否则决定是否进入阶段 B |
| 3 | 阶段 B 完成 | 13,860 | 最终判定 |

补充规则：

- 中期只算**主对比**（hetero，E−I0，四模型等权），不看其他对比，避免选择性停止。
- 中期报告必须连同 look 次数一起报告，并在论文中写明"结果来自第 k 次 look 的群序贯设计"。
- 若在 look 1 停止，后续阶段 A 的剩余条目仍可继续执行，但只能作为**独立复现**报告，不并入主估计。
- 该补记时间早于任何 outcome 计算（截至补记时只观察过条数，未读取任何 score）。
