CHAPTER 00

如何使用这份教程

从零开始理解一个研究项目，再学会判断证据能说明什么。

这份教程假定你没有做过科研、没有发表过论文，也不知道实验表格里的字母和统计术语。你可以把整个项目看成一次关于“AI 怎样在规定时间内把工作交出来”的调查。它涉及大模型，但核心问题用日常经验就能理解。

你将依次学到：项目在问什么 → 一个实验怎样运行 → 三轮研究为什么发生变化 → 如何读懂结果 → 与别人做过的研究有什么关系 → 目前哪里可靠、哪里需要修正 → 怎样继续成为一篇论文。

页面中的教学示例是为理解原理而编的；历史统计来自已有报告；当前审计快照来自本次只读检查；探索性分析是发现问题后的诊断计算。四种材料不能混成同一份正式结论。

CHAPTER 01

1．这个项目到底在研究什么

一个会做事的 AI，能不能在截止时间之前合理地停下来？

1.1 从赶作业理解问题

假设你还有 3 分钟交一份报告。再查一个资料可能让报告更好，但可能要花 40 秒；整理和点击提交也要花时间。你必须在“继续改进”和“先把已有成果交出去”之间选择。

如果你查到了很多资料，却在提交前超时，那么实际收到报告的人可能什么都没有。这时，研究“查资料的能力”还不够，还必须研究停止与交付的能力。

AI 智能体也面临同样的问题。它可能反复调用搜索、数据库或代码工具；每次调用都要等待，模型决定下一步也要时间。告诉它“还剩 30 秒”，并不能保证它知道下一次思考和调用会不会用掉这 30 秒。

1.2 项目把大问题拆成三个问题

层次问题对应研究
信息呈现把工具以前花了多久整理成一个数字，AI 会做得更好吗？S1
决策条件当继续与停止确实有取舍时，更准确的时间数字有帮助吗？S2
执行控制如果框架直接拒绝危险调用、替 AI 提交，结果会怎样？S3

1.3 一个可以检验的假设

“AI 时间观念不好”太宽泛，难以直接检验。更好的表述是：在固定任务、时间预算和模型服务下，自适应延迟摘要是否比固定摘要提高截止前得分？ 这句话指定了干预、对照、环境和结果，别人可以照着再做一次。

研究结论的范围由实验决定。本项目主要使用人工设计的收集任务，所以即便发现明显收益，也不能立即宣布“所有 AI 智能体都应该这样做”。

先记住
把信息告诉模型，是改变模型收到的输入；由框架直接限制行动，是改变系统实际允许发生的事情。两种干预可能有效，也可能无效，需要公平对照。
CHAPTER 02

2．先认识实验里的角色

模型是作决定的部分，实验程序负责计时、执行和记账。

2.1 角色与职责

词语直白解释本项目里的例子
大语言模型 / LLM读取输入、生成下一步动作的模型服务GLM、Qwen、DeepSeek、MiMo 的 API 模型标识
智能体 / Agent模型与反复执行动作的程序组合读状态 → 决定 fetch 或 submit → 收到新状态
工具 / Tool模型请求程序执行的操作fetch(K03)：获取 K03 对应的内容或积分
宿主 / Host真正运行实验的电脑与 Python 程序保存已获取物品、注入等待、验证分数
运行框架 / Harness管理智能体循环、规则和截止时间的程序runner、policy、clock 等组件
观察 / Observation这一轮发给模型的状态快照问题、工具说明、剩余秒数、已收集物品
动作 / Action模型返回的结构化决定fetch、submit，S3 还有 commit
轨迹 / Trace一局中每次请求、动作、等待、结果的记录events 中的 model_request、tool、forced_submit
验证器 / Verifier按预先写好的规则计算得分的程序已成功取得的不同物品值之和

2.2 一局中的循环

宿主生成状态时钟、题目、已有结果
↓
模型生成动作这一段也消耗墙钟时间
↓
宿主检查并执行允许调用、拒绝，或提交
↓
更新状态，再开始一轮直到提交、截止或异常

模型本身不直接修改得分文件。它输出动作，宿主验证后执行。这样可以知道积分是否真实来自工具，而不是模型凭空编造。

2.3 本实验有没有训练模型？

没有对这些模型进行训练或微调。 项目通过 API 调用已有模型，改变它们看到的信息及外部执行规则，再观察行为和分数。因此，它属于受控评估与系统干预研究。论文可以研究系统和行为，不要求一定提出一个新神经网络。

2.4 为什么模型名称不能当作纯能力排名？

这里测到的是“模型 + 提供商服务 + 默认推理设置 + 网络 + 实验协议”的组合。一个模型如果排队更久，会在同样 180 秒内完成更少轮调用。它得分低，未必是理解能力低；也可能是推理模式、服务负载或请求尾部延迟造成的。

先记住
同一个模型服务在不同时段也会变化。记录 API 模型标识，不等于已经固定模型权重、路由和解码设置。论文必须说明这个限制。
CHAPTER 03

3．用一局小实验理解所有规则

时间用完之前，“手里有成果”和“已经交付成果”是两回事。

3.1 一个教学示例

这一局有 100 秒。每拿一个物品得到 5 分。每次让模型作决定需要 8 秒，每次工具需要 16 秒。如果模型选择提交，也必须先生成一次 submit 动作，因此提交请求需要 8 秒。以下数字是教学例子，不是实测数据。

时刻发生什么已收集的分值正式结算得分
0—8 秒模型决定取第 1 个0尚未结算
8—24 秒第 1 次 fetch 完成5尚未结算
24—48 秒第 2 次决定与 fetch 完成10尚未结算
48—72 秒第 3 次决定与 fetch 完成15尚未结算
72—80 秒若现在决定 submit1515
72—96 秒若继续取第 4 个20尚未结算
96—104 秒此时才生成 submit，超过 100 秒截止200

这个规则人为制造了真正的停止取舍：少取一次，可能保住 15 分；多取一次，可能变成 0 分。现实任务不一定全额清零，这也是之后必须做真实任务验证的原因。

3.2 动作长什么样？

{"type":"tool","name":"fetch","arguments":{"item_id":"K03"}}
{"type":"submit"}
{"type":"commit","reserve_s":20}

第一行表示取 K03。第二行表示结束本局并结算，S2/S3 不要求模型把所有物品再抄一遍。第三行是 S3 的承诺动作：声明预留 20 秒。是否执行这个承诺，由所在实验组的规则决定。

3.3 请亲手调整停止规则

教学演示 · 固定时长的一局非实测

演示策略：只要“下一次请求 + 工具”结束后还剩设定预留时间，就继续取；否则发起一次有耗时的模型提交。每件 5 分，最多 20 件。等于截止时刻视为失败。它展示预留取舍，不模拟真实模型行为，也不复现 S3 的自动提交实现。

3.4 一个特别容易混淆的实现细节

在真实 S3 中，模型主动 submit需要模型返回动作，因此消耗一次请求时间；框架 forced_submit则直接在循环检查点由宿主结算，代码没有为它再发一次模型请求。框架仍然要担心上一轮模型或工具是否先超时，但不能把这两种提交都描述成“同样需要额外一次推理”。

代码核对所得
预留公式考虑请求尾部，不代表自动提交本身又调用了模型。教程演示与真实实现的区别会影响因果解释，必须明确写出来。
CHAPTER 04

4．时间为什么比想象中复杂

一局的耗时包含推理、网络、排队、工具等待和程序开销。

4.1 墙钟时间与 Token

墙钟时间（wall-clock time）就是现实经过的秒数。Token 是模型处理文本的单位。生成同样多 Token，在不同硬件、排队负载和服务路由下，花的秒数可能不同。搜索工具可能只返回很短的文本，却等了几十秒。因此 Token 预算不能直接替代截止时间。

一局总时间 ≈ 所有模型请求耗时 + 所有工具耗时 + 重试及程序开销

这里的“模型请求耗时”不仅是 GPU 运算，还可能包含网络传输与服务排队。仅凭客户端轨迹，通常不能把这些部分彻底拆开。

4.2 为什么平均值不够？

假设 10 次请求的耗时为 5、5、6、6、6、7、7、8、9、70 秒。均值是 12.9 秒，中位数是 6.5 秒。大多数请求很快，但偶尔一次 70 秒就能让整局错过截止。这种右侧有少量很大值的分布，被口语化称为“长尾”。

p50是中位数；p90是第 90 百分位，表示约九成观测不超过这个值。它们是在描述耗时分布，不是“成功率 90%”或“结果有 90% 的可信度”。本项目每局用最近最多 5 次请求估计 p90，样本很少，估计会很不稳定。

4.3 工具耗时与模型耗时要分开

项目可以人工控制工具等待，却不能完全控制远端模型何时返回。把工具改成固定 8 秒，也不能消除模型自身请求的随机性。因此“工具轻尾”不等于“整个系统没有尾部风险”。

4.4 注入等待到底是什么？

工具的本地计算通常很快。程序通过异步等待补足指定耗时，模拟慢数据库、搜索或其他外部服务。异步等待不会持续忙算，但真实时间照样流逝。实验测量的是模型如何应对这种延迟，不是数据库自身的性能。

4.5 休眠、中断与截止

本项目使用连续计时并检测宿主休眠。如果电脑睡了几分钟，不能假装这几分钟从未发生。休眠与进程被杀又不完全相同；只留下 started 标记时，还需要检查 journal，确认请求是否真的发出。标记太旧本身不足以证明“模型从未被调用”。

先记住
完整等待了多久、被截止截断前等了多久，是不同的观测。把超时请求的已等待秒数当成完整耗时，会低估尾部。这叫删失（censoring），后文会再解释。
CHAPTER 05

5．怎样设计一个能回答问题的实验

实验需要让不同解释有机会被区分。

5.1 自变量、因变量和混杂因素

概念在本项目中是什么为什么重要
自变量 / 干预提供固定摘要、动态摘要或执行护栏研究者主动改变的部分
因变量 / 结果截止前成功率、最终得分、是否提交用来判断干预效果
控制变量任务、预算、模型设置、工具规则尽量让组间差别来自干预
混杂因素某组恰好在服务更慢的时段运行可能造成看似是干预的差异
基线 / Baseline不加新摘要或不加护栏的方案提供比较起点
消融 / Ablation只保留自动提交，移除调用拒绝拆出整体方案中谁在起作用

5.2 为什么要配对和轮换顺序？

比较两种药物时，不应让一组都是年轻人、另一组都是老年人。同样，比较两种 Agent 规则，应尽量用同一个模型、同一个任务实例和同一种延迟环境。将这些匹配在一起，称为配对或分块。

但 A 总在上午、B 总在晚上也不公平。项目在 block 内轮换或安排各组顺序，以减轻时段影响。轮换能减轻漂移，却无法保证中途服务故障对各组的影响彻底相同。

5.3 一道题重复十次，不等于十道不同题

重复运行能估计随机性，但不会自动增加任务的多样性。S3 有成千上万条 episode，异质族的任务实例却是 16 个，且都是同一种人工收集场景的变体。统计时必须保留这层结构，不能把所有 episode 当成互不相关的全新研究对象。

5.4 先检查“这条信息有没有机会改变动作”

如果规则要求拿齐全部材料才得分，中途停止永远是 0 分，那么更准确的耗时摘要未必改变有机会成功的行动路径。它最多告诉你这一局是否赶得上。这个问题叫决策杠杆：信息是否有机会改变一个影响得分的选择？

还要问信息是否冗余。如果每次工具耗时已经逐条显示，再给一个平均数，可能主要是在节省计算或提高显著性，并没有增加原本未知的事实。冗余摘要仍可能有用，只是不能把它写成“新增了模型无法知道的信息”。

科研表述练习
设计有弱点，不代表实验毫无价值；它意味着结论要缩小。S1 的合理结论是“这套设计没有检出摘要收益”，不能写成“已经证明任何时间摘要都没用”。
CHAPTER 06

6．S1：先问“延迟摘要有没有帮助”

第一轮正式实验有 1,080 局；它得到一个不确定的零结果，也暴露了设计局限。

6.1 模型要完成什么任务？

S1 主要有证据检索和表格处理两类任务。模型需要获取要求的材料，完成计算，并提交正确答案和对应证据编号。必须满足验证器要求才算成功，少取或引用错误材料都会失败。预算为 150 秒。

6.2 A、B、C 只改变什么？

S1 条件增加的字段生活类比
A没有额外的耗时参考摘要可以翻看每次实际等了多久
B开局校准样本的固定均值老师说：以前平均要 3 秒
C最近最多三次同类工具调用的平均耗时助手每轮重新算一下最近的平均等待

所有条件都能看到时钟、历史动作及逐次耗时。因此 A 不是“完全没有时间信息”，B/C 的区别也不等于“不知道时间”与“知道时间”。

6.3 延迟怎样变化？

剖面工具耗时目的
stable_fast始终约 2 秒参考没有过时的稳定场景
fast_to_slow先 2 秒，经过预算约 8% 后变 15 秒检验旧参考是否因变慢失效
slow_to_fast先 15 秒，后 2 秒观察改善时是否更新行为

规模为 3 模型 × 20 任务 × 3 条件 × 3 剖面 × 2 重复 = 1,080 局。主对比提前指定为 fast_to_slow 中的 C−B，避免跑完后从许多表格中挑最漂亮的一项。

6.4 结果怎么读？

1,080 局中 902 局成功。主对比是 +0.83 个百分点，95% 区间［−5.83，+8.33］。方向略为正，但区间同时容许负效应和正效应，不能确认明确收益。

6.5 为什么这轮没有给出强结论？

  1. 停止缺少收益：材料不齐通常得零分，所以早停不能像后续实验那样保住部分分数。
  2. 很多成功局很宽裕：不少任务提前完成，时间估计再准确也未必提高已经成功的结果。
  3. 信息有冗余：动态摘要主要重算模型已能看见的耗时记录。
  4. 样本与置信区间：主条件每模型每格 40 局，结果不足以排除中等幅度的差异。

S1 还归档了 10 次宿主休眠影响。报告按既定规则保留失败，并做环境敏感性检查。它们属于运行环境证据，不能直接解释为模型不会守时。

先记住
“没有达到统计显著” ≠ “两组完全一样”。若要证明收益足够小，需先设有实际意义的等效界值，再做相应的等效分析。
CHAPTER 07

7．S2：让继续与停止真正有取舍

7.1 环境怎样变化？

10．均值、配对差与置信区间

统计不是给结果盖章，而是让不确定性变得可见。

10.1 先理解差值

E−I0=+5 分，表示在指定聚合口径下，执行组平均比基线多交付 5 分。如果 I0 是 10 分、E 是 15 分，那么绝对变化为 +5 分，相对变化为 +50%。这既不是“提高 5%”，也不是“提高 5 个百分点”。

成功率从 80% 升至 85%，绝对变化为 5 个百分点，相对变化为 5/80=6.25%。S1 的 +0.83 个百分点对应比例差约 0.0083，不是 +0.83 的比例差。

难度本身的巨大波动会影响两组。先比较同一任务上的差值，能减少任务难度造成的噪声。若两组来自不同任务，差值可能只是抽到了不同难度。

10.3 重复与模型等权

可先对同一模型、同一任务、同一区制、同一组的重复结果取平均，再算配对差；再按预定规则平均区制、任务和模型。顺序必须与目标效应一致。

假设模型甲跑 100 局，平均收益 +1；模型乙跑 10 局，平均收益 +9。按局数混合约为 +1.73；模型等权是 (+1+9)/2=+5。两者回答不同问题。本项目主指标希望四个固定模型权重相同。

10.4 bootstrap 是怎样工作的？

  1. 先得到每个任务簇的配对结果，保留其内部模型、组与重复结构。
  2. 从这些任务簇中有放回地抽样，形成一个与原来同样大小的伪样本。
  3. 重新计算平均差；重复许多次，观察估计怎样变化。
  4. 取估计分布约 2.5% 与 97.5% 的位置，得到一种 95% 百分位区间。

“重复 10,000 次 bootstrap”是对已有数据重采样，不是又向模型发了 10,000 次请求。它不会创造新的独立任务，也不能修复设计混杂。

10.5 95% 区间怎么解释？

例：+4.98［+4.20，+5.77］说明在采用的抽样、聚类和分析假设下，这个区间方法给出的不确定范围在零以上。它支持该分析下的正向效应。

严格的频率学解释是：如果按同一过程重复采样并构造区间，长期约 95% 的区间覆盖真实参数。不能把它读成“真实值有 95% 概率就在这一个固定区间内”，也不能说“95% 的单局都能多得 4.2—5.77 分”。

区间只覆盖分析考虑的不确定性。错误分组、服务中断、看过结果再改规则、任务缺少代表性，都不会因为区间很窄而自动消失。

11．p 值、显著性与“没有差别”

把几个常见误解拆开，才能避免把初步现象写成定论。

11.1 p 值回答的是什么？

假定没有组间效应，并且检验所需的随机化或分布假设成立，p 值衡量“观察到至少这么极端结果”的概率。它不是“假设为真的概率”，也不是“论文有多大概率能发表”。

项目的符号翻转检验，会将任务层面的差值随机翻成正或负，构造没有系统方向时的参照分布。其有效性依赖配对和交换性等条件；不能只因为调用了函数就认定设计偏差已经被解决。

11.2 为什么不能写 p=0？

本项目用 2,000 次随机翻转，并采用 (命中次数+1)/(2,000+1) 的计算。即使命中 0 次，报告值仍是约 0.0005。表格显示 0.000 往往只是小数位截断，应改为 p≈0.0005 或恰当的不等式。它也不是穷举所有可能排列得到的“精确 p 值”。

11.3 四种不同问题

你想知道什么需要的证据不能拿什么替代
有没有可检出的差异差值、区间与适当检验不能只看两根柱子高低
差异有没有实际价值预先定义最小有意义收益，结合成本与风险p 很小不能替代收益大小

11.4 多重比较：看得越多，偶然发现越容易出现

如果从几十个模型、区制和指标中挑出一项 p<0.05，再把它写成主要发现，就容易过度乐观。应预先指定主对比；其他分析标为探索，必要时采用多重比较校正。相关性会影响具体概率，所以不能简单假设所有比较独立。

11.5 统计功效与最小效应

功效是：如果存在某种指定大小的真实效应，实验有多大概率检出。它受独立任务数、变异、配对质量、阈值及效应大小影响。1,000 局不必然比 100 局更有说服力，关键还看它们来自多少有代表性的独立单元。

11.6 中途看结果、提前停止与预注册

预注册是先记录问题、样本量、主指标、排除规则和分析办法，再收集正式结果。它减少“看见结果后挑说法”的空间，但不保证设计正确。本地方案和源码冻结可以提供记录；若要更强的时间可信度，还可使用外部时间戳或公开登记。

群序贯设计允许预先安排几次分析，并为这些分析分配错误率。Pocock 边界是其中一种方法。具体边界依赖分析次数、信息比例、单/双侧检验及联合分布，不能照抄一个 z 阈值就声称严格控制了错误率。

三个效应单位不同，不能相加得到“总收益”。S1 与 S2 的条件字母也不能直接当作与 S3 同一种策略。

12.3 如何拆出得分的来源？

假设策略甲收集 20 分，但只有一半的局来得及交；策略乙收集 18 分，九成能交。粗略地看，甲的交付可能低于乙。实际期望得分应写成：

E[最终得分] = P(成功交付) × E[收集分值 | 成功交付]

不能直接用“平均收集分值 × 提交率”替代右式，因为收集多少与能否提交可能相关。项目现象更像减少已完成工作损失，但要区分收集质量改善、停止提前与自动结算，仍需要消融。

12.4 为什么信息组得分下降值得研究？

I1 在 hetero 中低于 I0，是一个可以继续调查的观察。可能涉及信息呈现、推荐排序、提示理解、时间判断或随机服务变化。检查“请求中位数没有变慢”只能排除某些简单解释，不能排除长尾、动作条件化差异和后续请求组成的变化。

12.5 为什么 GLM、Qwen 的收益不同？

如果基线几乎总能交付，护栏改善空间有限；如果模型在整局内只来得及取一两件，护栏也没有多少成果可挽救。这个解释合理，但四个服务只有四个点，无法建立稳健的一般规律。应报告分模型结果，并用独立延迟干预检验解释。

把结果写准确
不要把“未发现 C 和 E 的明确差异”改写为“阈值来源不重要”。现有区间仍容许一定差异，且两组的承诺流程也不同。

17．当前问题清单：为什么重要、怎样修

问题按对研究结论的影响排列；以下是审计发现与建议，不表示已完成修复。

优先处理

17.1 计费保护与重启链不匹配

事实：适配器看到 balance/byok 或正费用就抛 unexpected_paid_billing，但 runner 的 service_error_flags 只保存了异常类型和状态码等部分信息。守护逻辑主要防凭据失败与“没有新增文件”，而余额保护仍会新增零分文件，可能绕过无进展保护。

影响：本应表示基础设施边界的异常，被统计成很多研究结局；响应里已有成本说明保护是在请求返回后触发，不能理解成“请求未发生、一定没有扣款”。本次未查账单。

建议：让额外计费保护成为批次级停止原因；保存脱敏错误类别；核验服务方案后再恢复。先保留原记录与审计清单，冻结何种异常如何处理。历史异常能否重跑，应依据是否真正执行、服务是否改变等事实决定，并披露规则。

因果解释

17.2 信息界面不是“唯一差别是执行”

事实：I1 有成本估计等字段，C/E/O 只有 harness_policy 等额外字段。源码与原始轨迹一致，且与冻结快照一致，因此不是采样后才发生的变化。

影响：现有数据比较的是策略包，无法纯粹分离同等信息下执行规则的因果贡献。

建议：在独立新批次中统一观察字段，再正交地改变是否拒绝调用、是否自动提交、阈值来源。旧批次如实改写，不能事后把轨迹说成另一种设计。

上界失效

17.3 O 组的“真实成本模型”不完整

事实：O 使用任务私有基础均值和 σ，但没有同步处理 light_tail 的 σ=0.15、slow 的 ×3 和 drift 的当前倍率；它与 E 的预留公式相同，仍不预知远端模型延迟。

采样为 D=exp(N(log(m)−σ²/2,σ²))。若 m 表示算术均值，正确的 q 分位为 m×exp(σzq−σ²/2)。当前 O 的式子 m×exp(0.6745σ) 少了 −σ²/2，不能称为该分布正确的第 75 百分位；实际区制还要另乘倍率、换用对应 σ。

影响：不能把 E≈O 写成“已经接近最优”，也不能用当前 O−I0 作为可靠的可回收价值上界。

建议：重命名旧 O 为其实际策略；新批次修正分布。即便修正，启发式阈值策略也不自动成为最优 oracle，应另建明确目标下的规划器或上界。

必要基线

17.4 缺少固定阈值与提交机制消融

疑问：是否只要“剩余 20 秒就宿主提交”，就能获得几乎一样的收益？如果是，自适应时间模型的新增作用就需要重新定位。

建议：加入开发集上选定并冻结的固定预留阈值，以及仅拒绝、仅自动提交、两者结合的对照。另设需要实际生成最终回答的任务，测量最终交付延迟与质量。

机制边界

17.5 负对照并未只移除一种风险

事实：light_tail 中执行收益仍很明显。它说明工具长尾并不是收益出现的必要条件；但仍有模型请求随机性、基础停止失败、自动结算特权等解释。

建议：工具延迟与模型请求延迟分别控制，固定一侧再改变另一侧；若用离线重放，必须说明强制停止会改变未来提示与动作，所以它不总等价于真实在线反事实。

推广范围

17.6 高局数、低场景多样性

事实：两任务族共享积累与提交结构；服务来自同一接入链路。S3 的主效应基于固定四模型，不能推广为全部模型。

建议：加入真实检索问答、代码修复或其他有交付质量的任务，在新题目上确认。根据可用资源选择一个做扎实，胜过把同一合成矩阵重复扩大。

18.1 当前最值得保留的研究发现

在一个必须及时提交才能保住成果的受控任务中，带强制停止与提交的运行策略，持续显示更高的交付得分。 这是一个可以继续验证的经验发现。它不要求你把所有信息干预都宣布无效，也不要求把每个机制都提前解释完。

18.2 最值得进一步问的问题

当模型已经完成了一部分工作时，外部停止规则能挽救多少价值？固定规则能做到多少？自适应分位数还多带来多少？在最终答案生成也需要时间、过早停止降低质量的任务里，收益是否仍然存在？

这组问题可以让项目从“又一个提醒模型看时间的提示”，发展成“关于有限时间下的交付控制与适用边界”的实证研究。

CHAPTER 20

20．接下来如何把它做成更可信的论文

按“整理证据 → 补关键对照 → 独立确认 → 写作投稿”的顺序推进。

20.1 阶段一：先让现有证据可用

  1. 核验整个运行与恢复链，处理额外计费停止原因；确认服务方案后再决定恢复。
  2. 制作不可变快照，逐项分类正常结果、模型/工具超时、服务异常、宿主中断、孤立 started、历史隔离记录。
  3. 预先写定本轮异常怎样纳入、排除、单列或重跑；尽量按与结局无关的客观规则，完整保留清单。
  4. 修正文稿的组别、信息字段、提交时序和 O 组身份，重新审计估计器、权重和敏感性。
  5. 同时报告原始口径和合理替代口径，不挑最有利数字。

完成标准：每个计划单元有清晰状态，论文表述能逐项对应代码和原始记录。

20.2 阶段二：用最小对照回答最关键疑问

建议条件改变什么要回答的问题
统一信息，无保护所有组同样看到成本与时钟固定信息基线
固定阈值自动提交阈值由开发数据选定并冻结一个简单规则能做到多少
自适应阈值自动提交同样提交机制，仅阈值自适应估计器还有没有额外价值
仅拒绝风险调用移除宿主自动结算准入控制是否单独有效
拒绝 + 自动提交组合两机制二者是否互补、是否有额外代价
纯信息建议显示与执行规则对应的建议，不强制告诉模型与实际执行在统一信息下差多少

这是建议矩阵，不是已经执行的新研究。不要为了维持旧故事而要求每个假设必须成立。如果固定阈值最好，正确结果就是这个；如果过于保守，应报告质量损失。

20.3 阶段三：增加一个真实任务族

可选一个“最终交付需要额外时间”的真实任务：检索问答要整合证据写答案；代码修复要保存补丁并运行检查；数据分析要形成实际报告。用与停止规则独立的标准评价最终质量，同时记录及时交付率、成本和耗时。

不要仅奖励宿主已经知道的已取物品总和。真实任务中，材料再多也可能没有连贯答案；提前结算未必就能保住同等价值，这恰好是重要的外部有效性测试。

20.4 阶段四：独立确认与功效规划

用新任务实例、新种子和事先冻结的分析。先定义最小有意义效应，例如“交付率增加多少才值得承担质量损失”，再依据开发方差估算所需独立任务数。若安排中期分析，要在采样前固定分析时点与合法边界。

20.5 阶段五：围绕最终证据写稿

可以围绕“硬截止下的成果保全与停止控制”组织主线：已有信息何时不足 → 简单执行机制的增量 → 固定与自适应的比较 → 请求/工具风险边界 → 真实任务的成本与质量取舍。S1/S2 可作为前期证据或补充研究，不必因为已经跑过就占据同等篇幅。

规划原则
当前最值得追加的不是一模一样的几千局，而是能区分两种解释的新对照。若新证据只支持简单兜底，应如实把贡献定位为这一机制的可靠评估与边界。

21.1 常见疑问

我不会高等统计，还能继续这个项目吗？

可以先理解数据单位、对照公平性、差值与不确定性，再在具体分析时学习所需统计。不要只运行脚本而不检查分母、权重、聚类与缺失规则。复杂推断可请有经验的人审查。

没有训练模型，会不会不算 AI 论文？

评估、基准、机制研究、系统设计与失败分析都可以是研究。价值来自新增知识和可信证据，不取决于是否训练了网络。但纯工程功能通常需要更强实验来说明其研究贡献。

很多实验零结果，是不是之前都白做了？

它们能帮助缩小问题、发现冗余和设计限制。要保留记录，避免把开发结果冒充确认性证明，也避免把全部历史堆在正文中。最终稿应围绕最可信、最有新意的证据组织。

出现服务错误，直接删掉不就可以了吗？

服务错误可能与时段、任务和组别有关，删掉会改变样本组成。应先分类，固定处理规则，保留原始结果，并做合理敏感性分析。无脑计零与无脑删除都可能误导。

已有论文也说框架执行有效，我还能做吗？

可以继续，但需找到明确的新问题，例如自适应相对固定规则的增量、实际交付成本、特定风险边界或真实任务中质量取舍。先读懂近邻研究，再决定最值得补的实验。

看到 p 很小，为什么还要补实验？

p 值不会修复不公平的对照、失效 oracle、服务中断或任务范围过窄。它只是在已有分析模型下描述随机波动的一部分。

电脑关机后为什么有 started，却没有结果？

调度时先记 started，完成后才写 episode。两者之间被杀就留下孤立标记。必须结合事件 journal 判断发生到哪一步，不能仅凭标记存在决定按零计分或直接重跑。

22.2 自己先回答，再展开参考解释

为什么 A 组不显示摘要，仍不能叫“没有时间信息”？

因为它仍能看到时钟、历史耗时和某些校准记录。摘要是对已有信息的整理，可能有认知便利，但不同于从无到有地提供时间事实。

+0.83 个百分点，[−5.83,+8.33]，应该怎么向同学解释？

当前样本估计动态摘要略高，但区间仍容许降低和提高成功率，不能确认收益，也没有证明两组等效。还要说明它来自 S1 的特定剖面与模型等权比较。

为什么 E≈O 不能说明方案接近最优？

当前 O 没有正确处理全部实际区制，分位数公式也有偏差；即便知道分布，采用同一启发式预留也未必最优，且它仍不知道模型未来延迟。

如果固定 20 秒自动提交与自适应同样好，你会怎样改论文？

报告简单基线足以取得主要收益，重新定位贡献为执行机制与适用边界；检查真实任务上是否仍成立，不强行声称估计器创新。

为什么排除服务错误后的更大收益不能直接当正式答案？

因为这是观察异常后提出的筛选，可能选择性保留某些任务和时段；现有估计器还可能混合不等的区制权重。它用于诊断稳健性，不替代透明的主分析和独立确认。

轻尾工具环境里护栏还有收益，能断言模型推理长尾就是原因吗？

不能。它削弱了“工具长尾是必要条件”的解释，但还有一般停止失败、随机请求、自动结算等因素。需要分别控制这些机制才能更确定。

22.3 你最终应该能讲清楚的一段话

这个项目研究 AI 在有限现实时间内怎样停止和交付。前两轮没有确认额外延迟摘要的预期收益，第三轮带执行约束的策略显示更高交付得分。但现在有大量计费保护中断、组间信息不统一和参照策略实现问题，所以需要先审计，再用公平基线、新任务和独立数据确认收益及边界。
